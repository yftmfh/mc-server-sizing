## MC 服务器到底吃什么配置

Minecraft 对单核主频的依赖远大于核心数量。1.18 之后这个特征更明显，拿一颗 2.9GHz 的老至强去开模组服，TPS 掉到 15 是常见结果，玩家会看到方块回弹、怪物瞬移。

社区里流传一个门槛：Java 版服务端建议选 CPU-Z 单核跑分 600 分以上的机型。这是玩家社区的经验口径，不是 Mojang 或云厂商的官方标准，但方向和 MC 的负载特征对得上。14900K、7950X、9950X 这几颗高主频 U 是社区里被反复提到的选择。

按雨云现有机型的实测跑分和主频，大致可以这样分：

- **i9-14900K / 14900KF**：6.0GHz，CPU-Z 单核 880 到 900 分，单核天花板，1.20+ 大型整合包和 50 人以上群组服的首选，价格也最高。
- **Ryzen 7950X / 9950X**：5.7GHz，Zen 4 / Zen 5 架构，单核紧咬 i9，Linux 环境下部分场景反超，高版本插件加模组混开性价比更好。
- **R9 5900X**：4.8GHz，单核 450 到 520 分，中高版本模组服、小型群组、基岩版轻量服的均衡档。
- **Gold 6146**：4.2GHz，中规中矩，纯净插件服够用，价格友好。
- **Platinum 8275cl / 8259cl**：3.9GHz，多核强但单核弱，低版本模组或高版本纯净插件能跑，有免费兑换套餐。
- **E5 2666v3**：2.9GHz，单核最弱，只建议超低预算挂机服和低版本小型生存，同样有免费档。

内存要分场景看，给一个统一数字会误导人：

| 玩法类型 | 内存基线 | 依据 |

| 纯净服 / 插件服（Paper 等） | 4核8G 可带 10 到 15 人在线 | PaperMC 搭建教程的推荐口径 |
| 大型整合包（ATM9 这类近 400 模组） | 10G 起步，10 人以上建议 16G | 整合包开服实践，8G 需开 swap 才能启动 |

## 开服时最容易踩的坑

买完机器进面板，真正会让人卡住的不是"怎么点启动"，是下面这几件小事。

**MCSM 只认 ZIP 压缩包。** 从 CurseForge 或网盘下载的服务端如果是 `.rar`、`.7z` 或 `.tar.gz`，得先自己解压再重新压成 ZIP 才能上传。上传前确认压缩包里带的是服务端而不是客户端。

**文件管理的"全选"只选中当前页。** 文件多的时候列表会分页，点全选只勾中当前这一页的文件，剪切到根目录后发现还有一半留在原处。多页要分次操作。

**NAT 模式下三个端口都要映射。** 面板 Web 默认 23333，守护进程 24444，MC 服务端 25565。只映射 25565 的话游戏能连，但面板打不开；三个都映射出去才完整。没有独立公网 IP 时，访问面板的地址要把 23333 换成你映射出来的公网端口，每个人的端口号不一样，别照抄教程里的数字。

**JDK 版本对不上，服务端起不来。** 1.12.2 及以下用 JDK 8，1.16 及以上用 JDK 17，更新的版本可以走 JDK 21。在面板里新建 OpenJDK 镜像时要选对版本，进程启动方式选"虚拟化容器"，环境镜像选对应的 `mcsm-openjdk:xx`，网络模式选 host。

**CentOS 7 装不上 MCSM。** 安装脚本会直接提示操作系统版本过低。换 Ubuntu 24.04 LTS 或 CentOS 8 以上。

**加模组不是把 jar 丢进去就行。** 原版 `server.jar` 不支持模组，得换 Fabric 或 Forge 端。模组分服务端模组和客户端模组，服务端模组必须本地和服务器都有、且版本完全一致，否则不生效。Fabric 端要先装 Fabric-API，不然其他模组一个都不加载。

**换存档后记得改权限。** 上传新地图替换 `world` 文件夹后，如果服务端是用非 root 用户跑的，要 `chown -R` 把目录权限给到那个用户，不然服务端起不来，日志里只报一行权限错误。

**首次启动要改 eula。** `eula.txt` 里的 false 改成 true，`server.properties` 里按需要调正版验证和端口，改完重启实例。

启动脚本里的内存参数按机器配置填，比如 `java -Xmx7G -Xms7G -jar paper.jar nogui`，两个值设成一样能减少运行时的堆调整开销。

## 哪些情况不适合选雨云

雨云的机房主要在国内，海外节点相对少。如果你的玩家分布在欧美或东南亚，延迟会比选海外机房高，这种情况该看有海外区域的综合云厂商。

对 SLA 要求 99.99% 以上的大型商业服也不合适。雨云定位是性价比，不是高端商用，真按商业合同跑服务得找能签 SLA 的那类厂商。

还有一类是需要在系统内核层面做大改的极客服主，比如自己编译内核、调网络栈、跑非标准容器编排。VPS 裸机能给你 root，但底层虚拟化不是你能动的，这类需求自建物理机更合适。
